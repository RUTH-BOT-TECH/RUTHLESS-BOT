# Ruthless MD — technical guide

> This guide preserves detailed implementation and provider notes. For the current quick-start, see the root README. Newly issued portable short session IDs include the trusted pairing-service HTTPS origin, so a bot deployer normally enters only `SESSION_ID` and `OWNER_NUMBER`; `PAIRING_API_URL` and `PAIRING_SITE_URL` are optional overrides or needed for earlier non-portable short IDs. Only use IDs from a pairing site you trust: the bot contacts the origin encoded in the ID.

## Pairing-service operator setup

1. Create a Render Web Service from this repository with root directory `pairing-site`, build `npm install`, and start `node server.js`.
2. Set `MONGO_URL` to the operator's private MongoDB connection string and `DATA_KEY` to a key generated privately by `node pairing-site/scripts/gen-key.js`. Never share these with bot deployers or put them in Git.
3. Render provides the service's HTTPS URL after creation. Set `PAIRING_SITE_URL` to that exact origin (no path or trailing slash is needed) in the service environment and redeploy. Render supplies `PORT`; the server cannot start pairing without its URL.
4. Open `/health` and perform QR and pairing-code tests using a disposable WhatsApp account. Publish the site link only after confirming delivery and restoring the bot session. The account and MongoDB must be operator-controlled, not exposed here.

## Legacy notes and feature reference

**2. Deploy the bot:** [Deploy to Render](https://render.com/deploy?repo=https%3A%2F%2Fgithub.com%2FRUTH-BOT-TECH%2FRUTHLESS-BOT) · [Deploy on Railway](https://railway.com/new) · [Deploy to Heroku](https://heroku.com/deploy?template=https://github.com/RUTH-BOT-TECH/RUTHLESS-BOT). Choose/import the bot repository on Railway. These configuration files deploy the bot only, not the separate pairing service. Verify that GitHub contains the latest tested changes before deploying.

**Experimental:** pairing-site and short-ID syncing are implemented locally and have local MongoDB/API tests, but neither QR nor code pairing, private delivery, nor reconnects have been tested with a real WhatsApp account. Do not use for important accounts or production until that testing and a security review are complete. Other requested batches remain unfinished. Baileys is unofficial and may change or restrict accounts.

## Bot setup

Node.js 20.19 or newer is required. Set `OWNER_NUMBER` and `SESSION_ID` in the bot environment; legacy non-portable short IDs also need `PAIRING_API_URL` and `PAIRING_SITE_URL`. Use international digits for the owner; the API URL must be the trusted HTTPS origin. The owner chooses `HEARTBEAT=on` to opt in; it defaults to off. Run `npm install` and `npm start`. `/health` returns 200 when connected, 503 otherwise.

Keep the pairing server's `MONGO_URL` and `DATA_KEY` out of bot environments. With no `DATABASE_URL`, settings are kept in local JSON and backed up to the pairing service for short IDs; an ephemeral host can lose local changes before upload. If you set `DATABASE_URL`, it must be **your own isolated database**, not shared credentials for a multi-tenant database. The bot uses one tenant document, but MongoDB credentials themselves grant whatever permissions the database user has. Existing legacy records are not migrated. The older `DATA_SERVICE_URL`/`DATA_SERVICE_TOKEN` adapter remains available separately; do not configure it alongside `DATABASE_URL`.

The legacy long snapshot `SESSION_ID` remains supported as a bootstrap for an empty store. It does not gain short-ID sync or remote settings backups. Direct bot-side pairing with `PAIRING_NUMBER` remains a legacy fallback and prints its pairing code to private server logs.

**Never run one session ID on two hosts.** WhatsApp can disconnect both. The short-ID path uses an exclusive server lease and stops on renewal failure. A local snapshot alone cannot prove no other host is active during an outage: this implementation therefore fails closed instead of connecting offline without a lease. If startup cannot reach the service after three attempts, it waits 60 seconds before exiting. Leases cannot eliminate every network-partition or suspended-process race; do not rely on them to run duplicates.

The bot’s owner number is the only privileged identity. Creator credit grants no permissions. If WhatsApp supplies a hidden LID without a trusted phone mapping, owner authentication fails closed. The creator credit is `2348021016309`.

`MODE=public` lets other users issue commands. `MODE=self` limits commands to the configured owner or messages sent by the linked account. `.language` stores a preferred translation language but does not translate the bot interface. Time and calendar use `DEFAULT_TIMEZONE`, or an optional IANA timezone argument. User counts are only unique senders observed since the database was created.

External services: `.weather` uses Open-Meteo geocoding and forecast APIs; `.changelog` uses GitHub releases. Neither requires an API key; GitHub can rate-limit requests. Profile pictures are served by WhatsApp and can be hidden. Configure personal data policies before deploying publicly. Some later features and deployment integrations are still incomplete.

## API rules for future batches

Prefer documented, currently active, free keyless APIs when suitable and permitted by their usage terms. Verify endpoint documentation and test the actual request when possible. Never invent endpoints or claim an untested service works. Each API-backed command must identify its provider and handle timeouts, rate limits, and failures with a clear fallback. If no suitable keyless option exists, use a documented free-tier option, name the exact environment variable and provide signup/key-creation instructions. For a missing required key reply: `This command needs <KEY>. Owner: add it in your environment settings.` At the end of each batch, list only the keys the deployer must create manually. Local commands use no external API.

Batch 1 API notes: Open-Meteo geocoding and forecast endpoints and GitHub's public releases endpoint returned HTTP 200 in a live check on 2026-11-04 (GitHub was checked against the public `nodejs/node` repository, not this project's future repository). Service availability may change. Open-Meteo's free service is intended for non-commercial use; consult its current terms for deployment. GitHub's unauthenticated API is rate-limited and `.changelog` needs a configured public repository with at least one release. API keys to create for Batch 1: none.

## Batch 2: group controls (still in progress)

Includes group actions, warnings, group metadata and settings, tags, native polls, bot-run voting, welcome/goodbye templates, slowmode, global read/reaction/presence toggles and table-driven protections. Group actions use WhatsApp via Baileys; image classification uses the bundled NSFWJS MobileNetV2 model with TensorFlow.js in a dedicated worker. No external scanning API or new API key is used.

**Autodl:** `.autodl on|off` is an owner-only global toggle and recognizes public GitHub repository links, public single-file MediaFire/Google Drive/MEGA links, TikTok photo posts, CapCut template-detail links, Instagram photo-post links, Instagram username story links and Threads post links, plus the yt-dlp-backed sites listed in Batch 4. It reuses the downloader code and enforces the 50 MB limit. Only one download per chat at a time and a 10-second per-chat gap are allowed. Site availability varies; failures produce a fallback reply. GitHub may rate-limit unauthenticated requests. Owner/admin checks and protections fail closed for LIDs WhatsApp has not mapped. Do not rely on these controls as the sole moderation system. `antitoxic` uses the same editable blocked-phrase list as `antibadword`; it is not a toxicity model. Bot-ID prefix detection is heuristic and may misidentify people; configure with `.botprefix add BAE5` before enabling it. Configure `.allowcountry add 234` before enabling antifake; this matches phone-number prefixes and skips unknown LIDs. Image classification is probabilistic; it can miss content or flag harmless images. The bounded scanner queue can drop work when full; it logs failures. It only scans still images and stickers, not videos. Inference runs in a worker thread with a maximum queue of 12 and a 50 MB media cap. It resizes to 224 by 224; Porn plus Hentai scores of 0.90 or more trigger the selected action.

Anti-delete keeps at most 500 recent messages in memory, for up to 30 minutes; it cannot recover messages seen before startup or outside the cache. View-once reveals and anti-delete replays can violate members' expectations of privacy; announce and obtain consent before enabling them. WhatsApp may not provide downloadable media or these events for every message. Group-info pictures use a bundled default image when unavailable; welcome/goodbye media still requires live testing. Vote state persists but does not yet time out; voting and warnings are not atomic across simultaneous messages. Slowmode/spam history is in-memory and resets on restart. All real WhatsApp event shapes and actions require live compatibility testing.

Suggested live tests with a disposable test group and a second account: make the bot an admin; try `.close` and `.open`, `.warn <number> reason`, `.antilink delete`, `.slowmode 10`, `.welcome on`, `.poll Question | Yes | No`, `.vote Question | Yes | No` and `.endvote`. Verify owner/admin exemptions, and repeat with the bot not an admin. Only test replay, view-once and scanning with informed consent. Avoid using a real group until these actions are validated.

LID/autodl live verification: GitHub returned a valid ZIP for `octocat/Hello-World` on 2026-11-04 using the implemented downloader. Baileys mapping storage, owner protection, and API failure cases pass local automated tests. End-to-end pairing, actual WhatsApp message delivery, and all WhatsApp LID/event cases still need testing with real accounts. If upgrading from an existing 6.x session, back up MongoDB and be prepared to re-pair if Baileys 7 rejects the prior credentials. Never run both versions on the same session concurrently.

## Batch 3: media

Implemented: stickers (including videos up to 10 seconds), sticker pack metadata, static and animated text stickers, Emoji Kitchen mixes, large emoji, sticker/media conversions, temporary media uploads, background removal, image filters, meme/watermark tools, and profile-picture effects. Media must be captioned with the command or replied to; the limit is 50 MB. For stickers, set `STICKER_PACK` and `STICKER_AUTHOR` in `.env`. `ffmpeg-static` provides an ffmpeg binary for supported npm platforms; other systems may need a compatible build or a project change. Test platform compatibility before deployment.

**Providers and fallbacks:** most processing is local. `.removebg` uses the IMG.LY small model locally without an API key; model inference can be slow and is limited to one job at a time. `.emojimix` uses the `emoji-mixer` offline metadata and Google Emoji Kitchen images; `.emoji` uses Twemoji assets from jsDelivr. `.tourl` uses Uguu, and creates a public temporary link: do not upload confidential media. Uguu, Google and jsDelivr can be rate-limited or unavailable; commands return a failure message. Uguu, Google Emoji Kitchen, and Twemoji were tested with harmless sample data on 2026-11-04. Results still need real WhatsApp testing. Uguu's advertised retention is about 48 hours; the provider controls actual retention.

**Licensing and model size:** `@imgly/background-removal-node` includes AGPL-3.0 licensing, which may impose source-availability obligations when the bot is distributed or offered over a network; review the dependency license before deploying or pushing. Its bundled model files are large (the package is roughly 127 MB installed). FFmpeg's bundled build is GPL-enabled; review its license too. The project archive omits `node_modules` and installs them through `npm install`.

**Limitations:** `.enhance` and `.hd` are local sharpening/contrast, not AI super-resolution; `.upscale` uses local resize. Profile effects are simple static renderings. WhatsApp image, sticker and animated-sticker delivery has not yet been tested with real accounts. Mobile/Termux and low-memory hosting compatibility of the native model, canvas, sharp, and FFmpeg dependencies needs testing; background removal requires significant CPU and memory.

Suggested test from a second WhatsApp account: reply to an image with `.sticker`, `.blur`, `.removebg`, and `.meme top|bottom`; reply to the sticker with `.toimg` and `.take pack|author`; try `.attp hello`, `.emoji 😃` and `.emojimix 😃+🔥`; try `.tourl` only with non-sensitive media. For animated stickers use a short video, then `.tovideo`. Verify oversize and unsupported inputs get an error reply.


## Batch 4: downloader progress

Install Python 3 and the pinned Python requirements before using yt-dlp-backed commands or TikTok slideshows. For example, on Linux/macOS:

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
# Set PYTHON_BIN=.venv/bin/python in .env, then npm start
```

On Windows, use `.venv\Scripts\python.exe`. The bot uses the bundled `ffmpeg-static` binary. yt-dlp, gallery-dl and curl-cffi (needed for certain provider connections) are pinned in `requirements.txt`; yt-dlp intentionally does not use browser cookies, plugins, remote components or user config. Only download media you have permission to save. YouTube and other providers can rate-limit, block servers, remove formats, or require login; commands then reply with a fallback. A public YouTube sample was actually searched and downloaded as MP3 and MP4 on 2026-11-04. A TikTok video, a SoundCloud track and a Bandcamp track were downloaded through the wrappers on 2026-11-04. The other site wrappers have not been verified end-to-end with real links; a Vimeo sample required login, and a Dailymotion sample failed. The local proxy rejects non-public IP destinations, but this is not a substitute for deploying untrusted downloaders in a properly isolated environment with egress and disk limits. At most two jobs per pool can run at once for yt-dlp, file hosts, TikTok slideshows, CapCut, and Instagram/Threads, in separate pools (up to ten across those pools); output is limited to 50 MB; no unrestricted arbitrary-URL downloader is exposed.

`.spotify`, `.deezer`, `.applemusic` and `.tidal` read public track information, search the iTunes catalog for a match, send an iTunes preview of up to 30 seconds if available, and try to find matching audio on YouTube; the audio is labelled a match, not an original file. Exact matches can fail and sources may block downloads. `.spotifysearch` searches **iTunes**, not Spotify, and labels its source accordingly. A Spotify sample returned metadata and a real preview on 2026-11-04; the matched full YouTube audio was blocked by YouTube during the same test. `.github` and `.gitclone` use GitHub's public API without a key and can be rate-limited.


**File hosts and APK search:** `.mediafire`, `.gdrive`, and `.mega` download only public single files, not folders or password-protected shares, and send them as documents; 50 MB per file, a 90-second timeout, and a shared two-job file-host limit apply. Google Drive files needing login or virus-scan confirmation beyond the supported direct endpoint return a fallback. MediaFire page structure can change. MEGA uses pinned unofficial `megajs` 1.3.10, requires the share key in the link, and uses HTTPS. Each host rejects redirects outside its provider-specific hostname allowlist; downloaders must still run with network egress isolation and resource limits. `.apk`/`.apkdl` use F-Droid's official search API and package API; name searches return up to five F-Droid listing links, while exact package IDs also return the suggested-version APK link. This searches F-Droid only, not all APK stores, and does not scan apps for malware; review publishers and use files you trust. All these commands are keyless and reply with a provider-labelled fallback if unavailable.

Live provider tests on 2026-11-04: MediaFire sample downloaded 31 bytes (`test.txt`), Google Drive sample downloaded 5 bytes (`spam.txt`), and a public MEGA sample downloaded and decrypted 394,690 bytes. F-Droid search for `notes` and package `org.fdroid.fdroid` returned valid results; its suggested APK URL returned HTTP 200 (12,426,276 bytes by HEAD). The four commands and autodl for all three file hosts also ran through mocked WhatsApp sockets against those providers. No real WhatsApp delivery was tested.

**Social and title additions:** `.tiktokslide` uses gallery-dl 1.32.19 to extract still-photo posts, then fetches and validates images through the public-IP proxy. Input must be a canonical `tiktok.com/@user/photo/id` link. Posts exceeding 20 slides or 50 MB total are rejected rather than intentionally truncated; sound and animated slide effects are not preserved. One-second gaps separate slide sends. `.capcut` reads the public template page's metadata and sends its associated MP4 preview, not an editable template project. It accepts `capcut.com/template-detail/<id>` or `/template-detail/<slug>/<id>` only, not short/watch links, and restricts redirects and media CDN domains. Both may fail if sites block the server or change their pages. `.imdbdl` uses IMDb's public **unofficial, undocumented suggestion endpoint** for title/year/cast and YouTube search for a possible trailer link, or a YouTube search URL if extraction fails. It does not fetch IMDb ratings or a full movie, and the trailer match is not independently verified. None requires an API key.

**Instagram, Threads and HappyMod:** `.igphoto` parses public Instagram embed data, validates the supplied post shortcode, and returns a photo or photo-only carousel (up to 20 images and 50 MB total). Mixed photo/video carousels and video-only posts return a fallback, not thumbnails. `.threads` uses public Threads page data and selects the exact post shortcode, with up to 20 images/videos and 50 MB total; media hosts and redirects are constrained to Meta CDN domains, media signatures are checked, and item sends have one-second gaps. ## Batch 5: AI progress

Text commands use the keyless **LLM7 OpenAI-compatible API** at `https://api.llm7.io/v1/chat/completions`, requesting **Mistral Nemo (`mistral-Nemo-Instruct-2407`)**. The `.chatgpt`, `.gpt4`, `.gemini`, `.claude`, `.llama`, `.copilot`, etc. names are compatibility aliases for the same Mistral model, **not** those brands' models; replies say which model was used. Text tasks include translation, summarization (also from a replied text message), rewriting, explanations, creative writing, math and coding. `.song-gen` produces lyrics, not audio. Answers can be wrong, out of date or rate-limited; provider errors return a fallback. Inputs are limited to 6,000 characters; responses are trimmed to 3,500 characters. At most two text jobs run at once.

Chat aliases keep the last 10 messages per user **per chat** in memory for 30 minutes of inactivity, with periodic expiration; state is lost on restart. `.clearchat` deletes your history for that chat. Other AI text tasks do not use chat history. Prompts and conversation history are sent to LLM7, a third-party service: do not send secrets or sensitive data. Group answers are visible to the group. This is not a substitute for a professional or fact-checked source.

`.imagine` and its aliases (including `.dalle`, which is **not** DALL-E) use the public volunteer-powered **AI Horde** image API at `https://aihorde.net/api/v2/generate/async`. It submits to `stable_diffusion`, requests one 512×512 image, checks job status up to 120 seconds, and sends a labelled result; the model name is taken from the returned generation. At most two image jobs run at once. Anonymous requests are low-priority, volunteers can be unavailable, and prompts are shared with volunteer workers. The request asks for non-NSFW and censored output, but this is not a guaranteed content filter. No manual API key is needed; the documented anonymous Horde credential is built in. Review AI Horde's and model licenses and privacy rules before use.

**Live checks on 2026-11-04:** the actual keyless LLM7 text endpoint answered a greeting, a translation and an explanation through mocked WhatsApp sockets; AI Horde produced an actual image through the command handler. No actual WhatsApp delivery has been verified. Image-to-image, avatar generation, local English OCR, local English transcription and vision were added afterward as described below.

**Test with a second WhatsApp account:** `.ai hello`, `.tr es Good morning`, reply to text with `.summarize`, `.code write a JavaScript palindrome function`, `.clearchat`, and `.imagine a red apple on a table`. Test no input, provider failure and queue timeout. API keys to create for this Batch 5 progress: **none**.

### Visual assets and image-to-image

The bot includes three original generated banners in `assets/menu/`; `.menu` selects one at random. `.alive` is text-only. `assets/default-pfp.jpg` is used when a profile or group picture is unavailable, including image effects. If an asset is missing, commands fall back to text or a built-in simple avatar. Replace these files with your own suitable JPG/PNG images to customize the bot.

Reply to an image with `.img2img turn this into a watercolor` or `.aiavatar futuristic illustrated portrait`. These use AI Horde's `stable_diffusion` image-to-image endpoint (not a face-recognition or identity-preservation guarantee). The photo and prompt are shared with third-party volunteer workers; only use images with the subject's permission, and don't submit private or sensitive photos. Input images are resized to 512×512 and output may vary. Anonymous jobs can fail, be filtered, or take up to about two minutes; errors receive a fallback. The provider was verified with a harmless generated avatar image on 2026-11-04; actual WhatsApp image delivery still needs testing. No key is required.

### Local OCR

Reply to or caption a JPG, PNG or WebP image with `.ocr`, `.readtext` or `.scan`. OCR is performed on the bot server using `tesseract.js` 6.0.1 and the bundled English `tessdata_fast` model. Images are **not** sent to a third-party OCR API. The pinned model comes from `https://github.com/tesseract-ocr/tessdata_fast` commit `87416418657359cb625c412a48b6e1d6d41c29bd` (Apache-2.0; license in `assets/ocr/LICENSE`), SHA-256 `7d4322bd2a7749724879683fc3912cb542f19906c83bcc1a52132556427170b2`. Recognition is English-only, may make mistakes, is limited to one concurrent job and a 10 MB input, and times out after 60 seconds. No OCR API key or model download is required after installation. Printed text is typically easier to read than handwriting. Live WhatsApp delivery remains unverified.

### Text to speech

`.tts <text>`, `.aivoice <text>` and `.text2speech <text>` generate an Ogg Opus voice note, using Google Translate's **unofficial**, keyless speech endpoint (`https://translate.google.com/translate_tts`). English is the default; use `.tts --lang=es Hola` to select a supported language. Text is limited to 180 characters, and at most two speech jobs run concurrently. The text is transmitted to Google in the request: never submit secrets or private information. This unofficial endpoint can change or be blocked/rate-limited and is not the official Google Cloud Text-to-Speech API. The command reports failures rather than pretending to work. Google audio was live-tested and converted to Opus on 2026-11-04; actual WhatsApp voice-note delivery still needs testing. No API key is required.

### Local voice transcription and image vision

Reply to a voice note with `.stt`, `.speech2text` or `.transcribe` to transcribe **English audio locally** using Whisper Tiny English, via `@huggingface/transformers` 4.3.2 and the bundled quantized model (`Xenova/whisper-tiny.en`, revision `79fb389fc764e7c395bd330e9531d9d32ada7049`, Apache-2.0). The 42 MB model is included in `assets/models/whisper-tiny.en`, with its license. Audio stays on the server. One job runs at a time, inputs are capped at 10 MB and 30 seconds, and the worker is timed out after 90 seconds. Whisper can hallucinate speech or make errors, particularly on silence, noisy audio or non-English speech. It is not a certified transcription service.

Reply to or caption an image with `.vision [question]`, `.describe`, `.caption`, `.identify` or `.whatisthis`. This sends a resized JPEG and the question to BlockRun's keyless `https://blockrun.ai/api/v1/chat/completions`, requesting `nvidia/nemotron-3-nano-omni-30b-a3b-reasoning`. BlockRun may substitute a different model; replies show the model ID actually returned. Images and questions are shared with the provider and its upstream. Use only images you have permission to share, and do not send private or sensitive photos. Images are limited to 10 MB; the outbound compressed image is capped to fit the provider's request limit. Model output may be inaccurate and the provider may return 429 when its free capacity is exhausted. Live tests on 2026-11-04 identified a letter and a numbered color image; availability varies. Real WhatsApp delivery is not verified. Both services need no API key.

### Games and reactions progress

Implemented so far: `.joke`, `.dadjoke`, `.darkjoke`, `.pun`, `.truth`, `.dare`, `.wyr`, `.neverhaveiever`, `.fortune`, `.8ball`, `.coinflip`, `.dice`, `.roll20`, `.lottery`, `.wheel`, `.rps`, `.trivia`, `.ttt`, `.connect4`, `.chess`, `.guessnumber`, `.mathquiz`, `.scramble` and `.hangman`. Each question has four options and ends after one answer or two minutes. The three group board games validate player turns and legal moves; chess uses `chess.js` and retains move history for repetition. There can be one active stateful game per chat; games expire after two minutes of inactivity. Expired state is swept on startup and approximately every 30 seconds. Group membership, mentions and actual WhatsApp delivery remain unverified with real accounts. Other games, reactions and economy remain unfinished.

### Event images and extra controls

Only menu, welcome and goodbye event messages use the event-image helper. Put JPG, PNG or WebP files in `assets/menu/`, `assets/welcome/` or `assets/goodbye/`. Welcome and goodbye folders start empty. The bot chooses a random image distinct from the last event image sent in that chat, storing the last content hash in the database. If no different file is available, it tries the member’s profile-picture card, then the bundled `assets/default-pfp.jpg` card, and finally text-only. With only one image, this fallback prevents an immediate repeat. `.eventimg on|off` is a group-admin setting; off makes all three events text-only for that group. Promote/demote, kick, warn and ban notices are text-only. Only one bot instance per database is supported.

Owner toggles: `.anticall on|off|block`, `.autoviewstatus on|off`, `.autolikestatus on|off`, `.alwaysonline on|off`, `.autobio on|off`, and `.setprefix <1–3 punctuation characters>`. `anticall block` never blocks the owner, the bot, or an unresolved hidden identity. Status likes also mark the status viewed; the in-memory queue holds at most 50 items and leaves a random 2–5-second gap between statuses. Auto-bio updates are at least 10 minutes apart. These features are off by default. Automatic status viewing and liking affect privacy; obtain consent and respect WhatsApp rules.

`.chatbot on|off` is a group-admin control in groups and owner-only for DMs. It sends normal messages and recent conversation context to LLM7, rate-limits to one reply per chat every 30 seconds, ignores messages from the bot itself and IDs matching configured bot prefixes, and cannot reliably identify every other bot. Inform group members before enabling it.

Group-admin `.antipromote`, `.antidemote`, and `.antileave` require the bot to be an admin. Admin reversals skip the owner, bot, unresolved targets and events whose actor cannot be verified. Anti-leave only attempts to re-add a member when the actor is verifiably that same member, never after a kick by someone else. It records one attempt per member permanently; if a re-add is rejected it tries to DM an invite link. Automatic re-adds and invite messages can conflict with members’ privacy expectations; obtain consent and review WhatsApp rules.

`.inactive [days]` / `.listinactive [days]` lists only members whose observed last message was more than the given number of days ago. It separately counts members for whom the bot has no observation history, and never removes anyone. The bot records per-group member message counts and timestamps. `.savestatus` copies a replied-to status to the requester’s private chat only when WhatsApp supplies an explicit status reference; it may fail when the reference is unavailable or media expires. Save only with permission. `.tickle @person` uses OtakuGIFs (`https://api.otakugifs.xyz/gif?reaction=tickle`) and converts the returned GIF to MP4; it can fail if the service blocks or rate-limits the host. No extra API keys are needed.

The extra controls, call/status event shapes, status reactions, group-guard actions, image delivery and status saving have passed simulated-socket tests only. They have **not** been verified against a live WhatsApp account; test with a second account and a consenting test group before using them.


## Pairing service (separate Render web service)

Set its Render root directory to `pairing-site`, build command `npm install`, and start command `node server.js`. Set `MONGO_URL`, `DATA_KEY`, `PORT`, and `PAIRING_SITE_URL` in **that service's** environment. Values belong in Render, not in source or chat. Generate a 64-character hex encryption key privately with `node pairing-site/scripts/gen-key.js`; save it securely. Losing or changing it without migration makes existing encrypted data unreadable. Never share the MongoDB credential or key with bot deployers. Put the service behind HTTPS; the local development server itself is HTTP.

The pairing page provides a QR or eight-character pairing code. It sends the warning and session ID as separate messages to the newly linked account, retries delivery, and never displays the ID on the page. It keeps pairing attempts in server memory; process restarts cancel them. Pairing is limited to three starts per IP per 10 minutes and API traffic has IP/token limits, but these are in-memory, per-process limits, not a distributed production rate limiter. Verify the trusted-proxy/client-IP configuration for the actual hosting platform. Use one service instance until distributed limits are added.

The short ID contains a random bearer secret. The database stores its hash, not the secret. Sessions and backups are AES-256-GCM encrypted at rest; the pairing service holds the decryption key and must be trusted. A per-record salted keyed hash, rather than the raw phone number, is stored. Each collection is scoped to the authenticated deployer; no tenant-list endpoint is provided. A previous session is retained, and version checks and a time-limited lease reject stale writes. Backups are capped at 10 MiB and the bot removes recognized expired cache/reminder/todo/cooldown/game/log records before upload while preserving protected categories. Log trimming happens on the bot **before** upload; the server does not inspect backup contents for cleanup.

The service sets 90-day TTL indexes; MongoDB's TTL deletion is asynchronous, not guaranteed at the exact deadline or on a daily schedule. The next opted-in heartbeat can warn after 60 days of inactivity. At most 20 submitted heartbeat error codes are retained; the endpoint accepts restricted error codes rather than free-form text. `.backupnow`, `.restore confirm`, `.mydata` and `.deletedata confirm` are owner-only. Deletion removes remote records but leaves local files; remove those separately if desired. No direct DATABASE_URL settings backup is made by this service.

If `HEARTBEAT=on`, the bot sends its version and host every 30 minutes; the service can store last-seen time and up to 20 supplied errors. When present, the bot sends a restricted error code, not free-form error text or chat content. The server checks the public GitHub latest-release API (cached for 30 minutes); when a newer stable semantic-version release exists, the bot can DM its changelog once per version. The repository had no latest release when checked, so the live update-notice path is not yet verified. API failures and repositories without releases produce no notice, and nothing is installed automatically. With heartbeat off these telemetry messages are not sent. Session synchronization and lease renewals still contact the service and update retention metadata.

**Testing:** run `npm test` at the root and `npm test` in `pairing-site`. Optional real-Mongo integration tests use a disposable database specified via `TEST_MONGO_URL`; they drop the test database they create. The local integration tests covered MongoDB 7, authenticated HTTP, encryption, two-deployer isolation, stale writes, leases, backups and restore. They use simulated WhatsApp sockets. Real WhatsApp QR/code pairing, ID delivery, network failure/restart and multi-host partition scenarios are not verified. Rate limiting needs a shared store for multi-instance deployment; audit all exposed endpoints and address dependency advisories before production.

### Batch 20 checks

- Pairing code or QR → link an account → warning and ID sent as two private messages; the site displays no ID.
- Short ID → authenticate and obtain a lease → restore the newest safe session and reject stale writes.
- Settings change → clean recognized temporary data → encrypted backup or an owner warning; protected records are retained.
- Owner requests deletion → delete remote records → stop the bot; local files remain.
- Opted-in heartbeat → send version and host → show an authentic newer-release notice if available; never install it.

Checklist before using a real account: test code and QR pairing, delivery retries, invalid/logout behavior, backup/restore, outage and renewal behavior, and duplicate-host protection with disposable accounts. Test the 90-day TTL policy on the actual MongoDB deployment. Review rate limiting, proxy trust, key storage and the four high-severity root dependency advisories. Site-only dependency audit currently reports zero known advisories. No production deployment or real WhatsApp test has been completed.

Operator-generated key: `DATA_KEY` — run `node pairing-site/scripts/gen-key.js` privately and set the resulting value only on the pairing service. GitHub release checks use its public keyless API and can return no notice when there is no release or the API fails.
